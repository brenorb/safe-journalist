# Feature 0003: AI Summarization

## Brief

Build automatic AI summarization that triggers based on entry count OR time delay (whichever happens first), producing actionable summaries by analyzing the last summary and all new notes since that summary. Summarization triggers immediately after N entries (default 3) OR after N seconds since the last entry (default 10s).

---

## Scope and Targets

- **Refactor data storage structure**: Move raw entries from `/data/<timestamp>.md` to `/data/entries/<timestamp>-entry.md` for clarity
- **Create `/data/summaries/` directory**: Store AI-generated summaries as `<timestamp>-summary.md`
- **Add automatic summarization logic**: After each entry is created, check two trigger conditions: (1) count-based: if >= N entries since last summary, trigger immediately; (2) time-based: schedule a delayed task for N seconds after the last entry. Cancel and reschedule timer on each new entry. Whichever condition is met first triggers summarization. Read the most recent summary (if any) plus all newer entries, then invoke encrypted AI call to generate a new summary with "most relevant and up to date actionable information"
- **Update storage helper**: Support both entry and summary writes with appropriate subdirectories and naming conventions
- **Add configuration**: 
  - `SUMMARY_TRIGGER_COUNT` (defaults to 3) - trigger after N entries since last summary
  - `SUMMARY_TRIGGER_DELAY` (defaults to 10 seconds) - trigger N seconds after last entry if count threshold not reached

---

## Implementation Details

### 1. Data Structure Refactor

#### Update `storage.py`

- Rename `write_text_markdown` to `write_entry` and change output path from `{base_dir}/{timestamp}.md` to `{base_dir}/entries/{timestamp}-entry.md`
- Add `write_summary` function that writes to `{base_dir}/summaries/{timestamp}-summary.md`
- Add `list_entries` function that returns sorted list of entry file paths from `{base_dir}/entries/` (oldest to newest by filename)
- Add `list_summaries` function that returns sorted list of summary file paths from `{base_dir}/summaries/` (oldest to newest by filename)
- Add `get_latest_summary` function that returns the most recent summary file path and its content, or `None` if no summaries exist
- Add `get_entries_since_timestamp` function that accepts a timestamp string and returns all entry paths created after that timestamp
- Add `count_entries_since_last_summary` function that returns the number of entries created after the most recent summary (or total entries if no summaries exist)

#### Update `api.py`

- Change `create_entry` endpoint to:
  1. Call `storage.write_entry` instead of `storage.write_text_markdown`
  2. After writing entry, call `storage.count_entries_since_last_summary()` to check how many new entries exist
  3. **Count-based trigger**: If count >= `SUMMARY_TRIGGER_COUNT` (env var, default 3), immediately add `summarizer.generate_summary()` to background tasks and clear any pending timer
  4. **Time-based trigger**: If count < `SUMMARY_TRIGGER_COUNT`, cancel any existing delayed task and schedule a new delayed task for `SUMMARY_TRIGGER_DELAY` seconds (env var, default 10s) that will trigger `summarizer.generate_summary()`
  5. Return the entry response immediately (don't block on summarization)

### 2. Summarization Logic

Create new module `src/safe_journalist/summarizer.py`:

#### `generate_summary` Function Flow

Function signature: `generate_summary(session: MapleSession, api_key: str, model: str, base_dir: str, client: httpx.Client)`

1. Call `storage.get_latest_summary()` to get the most recent summary and its timestamp (if any)
2. If no summary exists, gather all entries from `storage.list_entries()`
3. If a summary exists, get its timestamp and call `storage.get_entries_since_timestamp(summary_timestamp)` to get only new entries
4. Read content from all relevant entry files
5. Construct a prompt for the AI:
   - **If there's a previous summary**: "Previous summary:\n{last_summary}\n\nNew notes:\n{new_entries}\n\nGenerate a concise 3-5 bullet summary with the most relevant and up to date actionable information for emergency contacts."
   - **If no previous summary**: "Notes:\n{all_entries}\n\nGenerate a concise 3-5 bullet summary with the most relevant and up to date actionable information for emergency contacts."
6. Call `encrypted_openai_call` with the constructed prompt using the same session creation flow from `cli.py`
7. Extract the summary text from AI response
8. Write summary to disk using `storage.write_summary`
9. Log success or errors (function can be called in background, so logging is critical for debugging)
10. Optionally return the summary path and content for potential manual/admin use cases

**Note**: This function can be invoked by either trigger mechanism (count or time), but will only run once since both triggers are canceled/cleared when either fires.

### 3. Automatic Summarization Trigger (Hybrid: Count OR Time)

#### Update `api.py`

- Add module-level variable to track pending delayed summarization task (e.g., `asyncio.Task` or timer handle)
- In `create_entry` endpoint, add `background_tasks: BackgroundTasks` parameter from FastAPI
- After writing the entry, implement dual trigger logic:
  
  **Count-based trigger (immediate)**:
  - Check `count_entries_since_last_summary()`
  - If count >= `SUMMARY_TRIGGER_COUNT` (default 3):
    - Cancel any pending delayed task
    - Add `summarizer.generate_summary()` to `background_tasks` immediately
    - Log "Triggering summarization: count threshold reached"
  
  **Time-based trigger (delayed)**:
  - If count < `SUMMARY_TRIGGER_COUNT`:
    - Cancel any existing pending delayed task (this resets the timer on each new entry)
    - Schedule new task to run `summarizer.generate_summary()` after `SUMMARY_TRIGGER_DELAY` seconds (default 10s)
    - Log "Scheduled delayed summarization in {delay}s (resets timer if entry already pending)"
    - This creates a "debounce" effect: timer only fires after {delay} seconds of no new entries
  
- Handle errors gracefully in both trigger paths (missing API key, encryption failures, no entries to summarize) and log them without failing the entry creation
- Use `asyncio.create_task` or FastAPI background tasks for the delayed execution

### 4. Session Management for API

- Cache session at module level or use lifespan to avoid recreating on every summarization
- Pass cached session and client to `summarizer.generate_summary()` when auto-triggered

### 5. Configuration

#### Update `api.py`

- Ensure `DATA_DIR` environment variable applies to both entries and summaries subdirectories
- Add `SUMMARY_TRIGGER_COUNT` environment variable (defaults to 3) - trigger immediately after N new entries
- Add `SUMMARY_TRIGGER_DELAY` environment variable (defaults to 10 seconds) - trigger after N seconds of inactivity
- Validate `MAPLE_API_KEY` is set at startup or when first summarization is triggered (log warning if missing, disable auto-summarization)
