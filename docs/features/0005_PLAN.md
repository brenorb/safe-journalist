# Feature 0005: Simple Web Frontend for Testing

## Brief

Create a minimal single-page web application that allows non-technical users to test the Safe Journalist system without using curl or CLI commands. The frontend will provide forms to create entries, view status, manually trigger summarization, and display the latest alert summary.

---

## Known Considerations

No directly relevant past solutions found in compound knowledge base. This is a new UI layer on top of existing API endpoints.

---

## Implementation Details

### 1. Static Frontend Structure

Create a simple single-page application using vanilla HTML/CSS/JavaScript that communicates with the FastAPI backend. No build step or framework dependencies required.

#### Create `static/index.html`

- **Layout sections**:
  - Header with app title and description
  - Entry form (textarea + submit button)
  - Status display (entries count, summaries count, next trigger info)
  - Latest alert/summary viewer (initially hidden)
  - Recent entries list (last 5 entries shown)
  
- **Key UI elements**:
  - Large textarea for composing entry text
  - "Submit Entry" button that POSTs to `/entries`
  - "Refresh Status" button that GETs from `/status`
  - "View Latest Alert" button that GETs from `/alert`
  - "Manual Summarize" button that POSTs to `/summarize`
  - Status indicator showing entries since last summary vs trigger threshold
  - Collapsible section for displaying alert content
  - Auto-refresh status after entry submission

#### Create `static/app.js`

- **API communication functions**:
  - `submitEntry(text)` - POST to `/entries`, handle success/error
  - `refreshStatus()` - GET from `/status`, update UI
  - `viewAlert()` - GET from `/alert`, display in modal/section
  - `triggerSummarize()` - POST to `/summarize`, show feedback
  
- **Event handlers**:
  - Form submission (prevent default, validate text, call API)
  - Button clicks for each action
  - Auto-refresh status after successful entry creation
  - Clear textarea after successful submission
  
- **Error handling**:
  - Display user-friendly messages for 404 (no summary yet)
  - Display error messages for failed requests
  - Show loading states during API calls

#### Create `static/style.css`

- **Styling goals**:
  - Clean, modern interface
  - Large, easy-to-click buttons
  - Clear visual feedback for actions
  - Responsive layout (mobile-friendly)
  - Readable text sizes
  - Color-coded status indicators (green=ready, yellow=pending, etc.)
  
- **Key styles**:
  - Container with max-width for readability
  - Card-style sections with subtle shadows
  - Button states (hover, disabled, loading)
  - Alert display with formatting for markdown-style summaries
  - Entry list with timestamps and preview

### 2. Serve Static Files from FastAPI

#### Update `src/safe_journalist/api.py`

- Add static file mounting:
  ```python
  from fastapi.staticfiles import StaticFiles
  from fastapi.responses import FileResponse
  
  # Mount static directory
  app.mount("/static", StaticFiles(directory="static"), name="static")
  
  # Serve index.html at root
  @app.get("/")
  def read_root():
      return FileResponse("static/index.html")
  ```

- No changes needed to existing API endpoints - they already return JSON suitable for frontend consumption

### 3. Add Entry Listing Endpoint

#### Update `src/safe_journalist/api.py`

Add new GET endpoint `/entries` to list recent entries:

1. **Route**: `@app.get("/entries")`
2. **Function**: `list_entries_endpoint(limit: int = 10)`
3. **Logic**:
   - Get `base_dir` using `get_data_dir()`
   - Call `storage.list_entries(base_dir)` to get all entry paths
   - Read last N entries (default 10, configurable via query param)
   - Extract timestamp from filename
   - Read first 200 characters as preview
   - Return list sorted newest first
4. **Response Model**: Create `EntryOut` model:
   - `timestamp: str` - entry timestamp
   - `preview: str` - first 200 chars of text
   - `path: str` - file path

## UI Flow

1. **User opens browser to `http://localhost:8000/`**
2. **Page loads with empty form and status**
3. **User types entry text and clicks "Submit Entry"**
   - Text POSTed to `/entries`
   - Success message shown
   - Textarea cleared
   - Status auto-refreshes
   - Entry appears in recent list
4. **User clicks "Refresh Status"**
   - GET `/status` updates counters
   - Shows "X of Y entries until auto-summarize"
5. **After 3rd entry (or manual trigger)**
   - User clicks "View Latest Alert"
   - GET `/alert` retrieves summary
   - Summary displayed in readable format
6. **User can click "Manual Summarize" anytime**
   - POST `/summarize` triggers background job
   - Shows "Summarization started" message

## Technical Notes

- **No build step**: Pure HTML/CSS/JS for simplicity
- **API base URL**: Hardcoded to `/` (same origin as server)
- **Error messages**: User-friendly (e.g., "No summary available yet" instead of "404")
- **Auto-refresh**: Status updates after entry creation to show progress toward trigger
- **Mobile-friendly**: Responsive design works on phones for field testing
